## 1. 지금 상태

화면은 이미 있고 돈다. 카드 셋이다.

1. `사람이 볼 항목` — findings 건수(히어로) + 등급 4개 + `목록 보기` 버튼
2. `가리킨 ID 가 실제로 있나` — `referenceTotal` + `reference` 5줄
3. `정의만 해 놓고 안 쓴 것이 있나` — `reqCoverage` · `reqCoverageWithDocs` · `scrCoverage`

부품도 이미 있다: `Meter` · `MeterRow` · `Card` · `FilterSelect`. **새로 만들지 말고 쓰라.**

- **`scrFuncCoverage` 는 축 이름 하나에 `to` 만 다른 9행**이다. `to` 에 문서 *종류*(`SCR`)가
  아니라 문서 *키*(`SCR-CMU`)가 온다 — 다른 축과 뜻이 다르다.

  선택지는 받은 데이터에서 만들어지므로 자동으로 들어간다.

**숫자를 코드에 박지 마라.** 위 값은 예시다. 실물은 dev DB 에 들어 있다(§6).

### 3-1. 라벨 (문자열 그대로 쓸 것)

| 자리 | 문자열 |
|---|---|
| 왼쪽 카드 제목 | `검사가 찾은 것` |
| 가운데 카드 제목 | `문서 사이 연결` |
| 가운데 위 블록 | `적어 놓은 ID 가 실제로 있나` |
| 가운데 아래 블록 (`triangle`) | `연결이 서로 어긋나는 곳` |
| 오른쪽 카드 제목 | `참고: 아직 안 쓴 것` |
| 접힘 줄 제목 | `화면의 기능이 기능명세서에 옮겨졌나` |
| 접힘 줄 부제 | `문서 N개 · 검사한 항목 M개` |
| 접힘 버튼 | `문서별 보기` / `문서별 접기` |
| 펼친 뒤 맨 아래 | `낮다고 틀린 것이 아닙니다 — 문서마다 기능을 적는 방식이 다릅니다` |

`referenceTotal` 줄의 라벨은 지금 코드대로 `전체` 를 유지한다(카드 제목과 겹치지 않게).

### 3-2. 무게

가운데(참조)를 **넓게**, 오른쪽(커버리지)을 **좁게**. 지금 그리드가
`minmax(0,12rem)_minmax(0,1.15fr)_minmax(0,1fr)` 인데 오른쪽을 줄여 대비를 준다.
**커버리지 3축을 숨기거나 접지 마라** — §4 의 계약이다.

### 3-3. `triangle` 표기

- `653/660` 과 **`7곳`** (못 채운 개수). 다른 미터 줄과 같은 `MeterRow` 를 쓰되 `gapNoun` 은
  `어긋남` 이 아니라 **`곳`** 이 자연스럽다 — `7곳 어긋남` 이 되게 하라.
- **분모 660 은 "전체 쌍"이 아니라 "대조 가능한 쌍"이다.** 양 끝이 다 말이 없으면 안 센다.
  그 뜻이 보이게 라벨이나 `title` 로 한 마디 남겨라: `양 끝이 다 적혀 있는 쌍만 셉니다`.

### 3-4. `scrFuncCoverage` 접힘 블록

- 기본 **접힘**. 밴드 맨 아래 한 줄.
- 펼치면 **문서별 9줄**을 `MeterRow` 로. 라벨은 문서 키(`SCR-CMU`) 그대로.
- 정렬은 **비율 낮은 순** (일이 어디 있는지 보이게). 같으면 문서 키 순.
- `gapNoun` 은 `아직 안 나옴`.

## 4. 뒤집으면 안 되는 것 — 전부 근거가 있다

1. **신호등 금지.** 빨강·초록·"합격" 표시를 붙이지 마라. `확인 필요 8` 은 *"8개가 잘못됐다"*
   가 아니라 *"8개를 사람이 봐야 한다"* 다. 실제로 앞 측정의 14건 중 6건이 문서 결함이 아니라
   저쪽 파서 한계였다. 미터 채움색도 한 색이다(심각도로 칠하지 마라).
2. **축을 하나라도 숨기지 마라.** 원래 9축(`reference` 5 · `referenceTotal` ·
   `reqCoverage` · `reqCoverageWithDocs` · `scrCoverage`)은 **상시 표시**가 계약이다.
   하나를 대표로 뽑으면 그게 *"정합성 = N%"* 라는 판정이 되는데 그 판정은 사람이 한다 —
   같은 데이터로 100% · 95.76% · 59.68% · 74.00% 가 다 나온다.
3. **`reqCoverage` 와 `reqCoverageWithDocs` 는 반드시 나란히**, 그리고 **둘 다 비율을 켜라.**
   한쪽만 비율이 보이면 나란히 둔 뜻이 사라진다(E2E V4 가 이걸 잡는다).
4. **`scrFuncCoverage` 의 합계를 만들지 마라.** `266/386` 같은 것을 띄우면 `0/4` 와 `98/98`
   이 둘 다 사라진다. 저쪽이 명시로 요청했다.
5. **UI 문구는 한국어.** 영문 약어·화살표(`FN→REQ`)를 쓰지 마라.
6. **시각 포매팅을 이 컴포넌트에서 하지 마라.** 서버가 만든 문자열(`measuredLabel`·
   `agoLabel`)을 받는다. 여기서 `toLocaleString`·`Date.now()` 를 쓰면 하이드레이션이 갈린다.
7. **스냅샷 비교 UI 를 만들지 마라.** "앞 측정 대비" 를 넣고 싶어도 넣지 마라 — 분모가 같이
   바뀌고(`54/54 → 58/59` 는 퇴행이 아니다) 집계 축이 달라서(같은 `check` 라도 `level` 이
   섞인다) 실제로 두 번 오판했다. 이번 범위 밖이다.
8. **`useEffect` 로 상태를 맞추지 마라.** 이 리포는 React Compiler 규칙
   (`react-hooks/set-state-in-effect`)을 켜 두었다. 렌더 중 조정으로 해결하라 —
   `reconcileFilter` 가 그 예다.

개수 표시(V13) · 한국어 등급(V14) · 축 9개 전부(V2) · 두 REQ 분모(V4) · 측정 시각(V3).

`scrFuncCoverage` 9줄이 각각 보이는가 · 접힘 상태에서 합계 비율이 안 보이는가.
